# Study Plan (no-rush pace)

Context: not actively interviewing — staying through bonus/promotion at JPMC. This plan is
paced for steady skill-building, not a sprint. Adjust the cadence up if a timeline appears later;
everything below still applies, just compress the weeks.

Target profile to prep for: Senior/Staff backend engineer, NY market, backend + infrastructure
(distributed systems, AWS, Kafka, data pipelines) rather than generic full-stack.

## Weekly cadence (aim for ~3-4 hrs/week, sustainable > intense)
- 2 algorithm problems (see `algorithms/` and `mock interviews/`) — rotate topics, don't grind
  the same pattern repeatedly. Track weak spots in `notes/`.
- 1 system-design doc read + think through how it maps to something you've built (see
  `system-design/`) — write a paragraph in `behavioral/my-stories.md` if a real story surfaces.
- 1 behavioral story drafted or refined (`behavioral/my-stories.md`) — five minutes writing beats
  zero minutes; don't let this become the thing you always skip.

## Phase 1 (now – ongoing): Foundation, no time pressure
- [ ] Read all of `system-design/` once, top to bottom — don't try to memorize, just build the
      vocabulary and notice which sections map to things you've actually done.
- [ ] Draft all 6-7 stories in `behavioral/my-stories.md`, even roughly. Refine later.
- [ ] Keep doing 2 algorithm problems/week from `algorithms/` — focus on the patterns you're
      weakest on based on `notes/`, not just easy wins.
- [ ] Once the insourcing project is finalized on your resume, add its story to
      `behavioral/my-stories.md` while it's fresh.

## Phase 2 (once promotion/bonus lands, still not actively applying): Depth
- [ ] Do 2-3 full mock system design interviews (self-run using the framework in
      `system-design/00-interview-framework.md` — pick a prompt, time yourself 45 min, write
      up what you'd say).
- [ ] Practice explaining your multi-region/Kafka/migration work out loud, not just in writing —
      pacing only reveals itself when spoken.
- [ ] Expand `spring-boot/demo-api` with one more non-trivial feature (e.g. add a Kafka producer/
      consumer to it, or an async job) so you have a live, walkable code sample if a take-home
      or "show me something you built" comes up.

## Phase 3 (when you decide to start looking, later): Execution
- [ ] Revisit `ROLE-RESEARCH.md`, refresh it — market moves.
- [ ] Update resume/LinkedIn with the insourcing project + new title.
- [ ] Start light networking/informational conversations before applying anywhere formally.
- [ ] Begin applying — at that point we can shift into active search mode (targeted role
      research, tailored resumes per posting, scheduling real mock interviews).

## Cadence reminders
- This is a marathon, not a sprint — you have runway. Consistency (3-4 hrs/week) beats binging
  and burning out.
- Revisit this file monthly and check off / adjust — it's meant to be edited, not static.
